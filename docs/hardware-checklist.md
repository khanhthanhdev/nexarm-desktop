# Hardware and environment checklist

Everything here was written and tested without a robot, a GPU server or a screen (engine tests use fake buses, the UI tests use a mock engine). Run these with the arm connected, then change **Status** to the date and result. Until then every item is reported as **not run**.

Keep a hand near the power switch for items 1 to 8: servos drop when torque is cut.

| #   | Check                                                      | How                                                                                                                                                                               | Expected                                                                                                                                                                                  | Status  |
| --- | ---------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------- |
| 1   | Soft joint limits                                          | Teleoperate slowly to each end of every joint. The limits come from the URDF (`nexarm_service/safety.py`, `SOFT_LIMITS`).                                                           | The arm never reaches a mechanical stop before the limit; if it does, tighten that joint's limit in `_URDF_LIMITS_RAD`.                                                                    | not run |
| 2   | Torque-on at connect                                       | Start a teleop session with the arm resting in a bent pose. Watch the first second.                                                                                                | No jump. If the arm moves when torque is enabled, rest capture happens too late (it runs after `connect()` enables torque); report it.                                                    | not run |
| 3   | Rest return on stop                                        | Move the arm far from where it started, stop the session from the app.                                                                                                             | The follower ramps back to its starting pose, then torque is released. No drop.                                                                                                           | not run |
| 4   | Lease expiry                                               | Start a session, then kill the desktop app (Task Manager).                                                                                                                         | After about 60 s the engine stops the session safely: arm returns, torque off.                                                                                                           | not run |
| 5   | Bridge mode exit and COM re-enumeration                    | Run and stop a teleop session several times on Windows.                                                                                                                            | The follower ESP32 restarts when bridge mode ends; the app reclaims its USB link within the retry window (about 25 s) every time, with no manual reconnect.                              | not run |
| 6   | Bridge mode with a WiFi client attached                    | Connect the follower over WiFi, then start an engine session on the USB port.                                                                                                      | Either it works, or it fails with a clear message. Record which.                                                                                                                         | not run |
| 7   | Calibration check at Home                                  | Put both arms at the vendor Home pose by hand; press "Check leader / follower".                                                                                                    | Per-joint differences within 40 ticks; a larger one points to a servo offset to fix on the Servo Advanced (follower) or Synchronizer (leader) page. Nothing is energised.               | not run |
| 8   | Recorded data trains                                       | Record 10 episodes from Lab: Record, compare `meta/info.json` with a `lerobot-record` dataset, train ACT on it with the existing script.                                           | Same `robot_type` (`nexarm_follower`) and features; training starts and the loss falls.                                                                                                   | not run |
| 9   | Deploy a trained policy                                    | Lab: Deploy, rollout with a checkpoint trained on this robot; then one trained on another robot type.                                                                              | The first runs and returns to rest on stop; the second is refused with a message naming the robot type.                                                                                   | not run |
| 10  | Coach: leader follows the policy                           | Lab: Deploy, Coach. Watch the leader while the policy drives; press Take over, Hand back, Hold, Reset to rest.                                                                      | The leader follows the follower (CMD 97/98 on the leader firmware), is free to drag during a correction, hands over without a jerk, and is returned to where it started when the session ends. | not run |
| 11  | Remote teleop, two machines                                | Station on one machine (Lab: Remote, listen on the tailnet address), operator on another. Drive, then unplug the operator's network and stop the operator.                          | The follower engages with a soft start, tracks the leader, and parks at rest within about a second of silence or a disconnect. Note the round-trip time shown.                           | not run |
| 12  | Remote training over SSH                                   | On a fresh Linux GPU server run `scripts/nexarm-gpu-bootstrap.sh`; in Lab: Train add the server, Test connection, run a short job. Repeat from Windows (OpenSSH client).            | Dataset uploaded, loss curve live, checkpoint downloaded and listed. A wrong key or host fails fast with a readable error.                                                                | not run |
| 13  | Layout and visual review                                   | Open every Lab page on a machine with a display (set `WGPU_BACKEND=dx12` on a VM). Switch to Vietnamese.                                                                            | No clipped or overlapping controls; the episode viewer shows the frame and the curve moves with the slider.                                                                              | not run |
| 14  | Engine lockfile                                            | In lerobot-nexarm, regenerate `uv.lock` with the uv version the repo uses (`uv lock`) so the new `service` extra is locked.                                                         | `uv sync --locked --extra service` succeeds in CI. A newer uv rewrites the lock format and adds unrelated churn, so use the repo's version.                                              | not run |
